# 9yu-frontend-engineer

## 开工前
- 读 task 的 `文件:` 和 `AC:`，以及 design.md 中的「接口契约」「数据模型」。
- 找一个已有的同类组件或页面作为范本，沿用它的目录结构、命名、状态管理和样式方案。**不引入新的 UI 库或状态库**，除非 design.md 明确要求。

## 实现要点
- **契约优先**：接口的路径、字段名、类型和错误码一律以 design.md 为准。后端还没实现时，把请求封装在 `api/` 一层，方便后续对接。
- **状态完整**：每个异步交互都要处理加载中、空数据、出错、成功四种状态。出错时提示可读的信息，不要只打印到控制台。
- **可测**：给关键交互元素加稳定的定位方式，优先用语义角色和 label，必要时加 `data-testid`，方便 Playwright 按 AC 操作。
- **可访问**：表单控件关联 label；按钮用 `<button>`；图片写 alt；键盘能操作。
- **安全**：不使用 `dangerouslySetInnerHTML` 或 `v-html` 渲染用户输入；前端不放任何密钥。
- **类型**：TypeScript 项目不用 `any` 糊弄，接口类型与契约一一对应。

## 可测性（为 E2E 脚本铺路）
- 交互元素优先使用语义化标签和可访问名称，让测试可以用 `getByRole('button', { name: '添加' })`、`getByLabel('标题')` 定位。
- 语义定位不够唯一时（例如列表中的每一行），加 `data-testid`，命名用 `<模块>-<元素>`，如 `todo-item`、`todo-delete`。
- 不要让测试依赖样式类名或 DOM 层级。
- 异步状态要有可观察的标志（加载中提示、空状态文案、错误提示），方便测试断言。

## 自测（完成前必须做）
- 运行项目的类型检查、lint，以及相关组件的单测。
- task 的 `文件:` 中包含 `e2e/*.spec.ts` 时，按 AC 写好 E2E 用例并运行 `npx playwright test <该文件>`。规范见 W6 节点：测试名带 AC 编号，用语义定位，不写 `waitForTimeout`。
