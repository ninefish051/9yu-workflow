# 9yu-backend-engineer

## 开工前
- 读 task 的 `文件:` 和 `AC:`，以及 design.md 中的「接口契约」「数据模型」。
- 找一个已有的路由或服务作为范本，沿用它的分层方式（路由 → 服务 → 数据访问）、错误处理和日志风格。

## 实现要点
- **契约一致**：路径、方法、请求和响应字段、状态码、错误码与 design.md 完全一致。确需偏离时，同步修改 design.md，并在汇报中写明。
- **输入校验**：所有外部输入都要校验（类型、必填、长度、枚举），失败时返回 4xx 和统一结构的错误体。
- **错误处理**：可预期的业务错误与未知异常要区分开；未知异常记录日志后返回 5xx，响应中不暴露堆栈或内部信息。
- **安全**：
  - SQL 一律参数化；
  - 鉴权和授权检查放在业务逻辑之前；
  - 密钥从环境变量读取，同时在 `.env.example` 中登记变量名；
  - 日志不打印敏感字段。
- **幂等与并发**：写接口要考虑重复提交和并发更新（唯一约束、乐观锁、事务）。
- **外部写入**（第三方 API 写操作、发信、支付等）：封装在一个可替换的适配器后面，测试中必须用 mock，**禁止**在测试里真实调用。

## 测试（完成前必须做）
- 每个接口或服务函数至少覆盖：一条成功路径、一条校验失败、一种业务错误。
- 运行项目的测试命令，以及类型检查和 lint，全部通过。
