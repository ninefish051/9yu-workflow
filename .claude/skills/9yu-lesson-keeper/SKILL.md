# 9yu-lesson-keeper：分层经验库

工具脚本：`python3 "$KIT/scripts/lessons.py" <cmd> "<项目>" …`，下文简写为 `lessons <cmd>`。

## 分层

| 层 | 位置 | 放什么 | 怎么被读到 |
|---|---|---|---|
| **L1 铁律** | `AGENTS.md` 的「铁律」小节（全文 ≤30 行） | 本项目每次开工都必须知道的规则，≤10 条 | 每个会话全量加载，Codex 也会读 |
| **L2 项目经验** | `docs/lessons/{pitfalls,decisions,patterns,env}.md` | 只在本项目成立的经验 | W3 按关键词和标签检索 |
| **L3 全局经验** | `~/.claude/9yu/lessons/<技术栈>.md`，通用经验放 `general.md` | 跟技术栈有关、换个项目也成立的经验 | W1、W3 按项目技术栈检索 |
| 本机信息 | `CLAUDE.local.md`（不提交） | 只在这台机器上成立的事实：本机路径、本机端口占用、本机工具版本差异 | Claude Code 自动加载 |

## 条目格式（一行一条，脚本靠它解析）

```
- (P012) [踩坑][vitest,env] 现象 + 根因 → 正确做法（来源: <项目名>/F01/T03, 2026-10-30, 命中 0）
```

- 编号：L2 用 `P`，L3 用 `G`。用 `lessons next-id "P" P|G` 取下一个编号。
- 类别（第一个方括号）：踩坑 / 决策 / 可复用 / 环境。
- 标签（第二个方括号）：2–4 个小写关键词，用逗号分隔。要包含技术栈名（如 `react`、`vitest`、`prisma`）和主题词（如 `env`、`auth`、`localstorage`），这是检索的关键。

## W7 流程

### 1. 记录命中
本批开发中，W3 检索出来、并且**确实用上了**的经验，执行 `lessons hit "P" <ID> …` 给它们的命中次数 +1。只是读到但没用上的不算。

### 2. 提炼（每批最多 3 条，宁缺毋滥）
回顾本批的这些内容：踩过的坑、W5 审查中被采纳的意见、W6 测试失败的原因及修法、做出的取舍。只保留**下次开工时能改变行为**的条目。

不要记录：
- 一次性细节；
- 代码里一眼就能看出的事实；
- 已经写在 specs 中的内容；
- 密钥、账号、个人信息。

### 3. 分层判断

按顺序问自己：
1. 只在这台机器上成立吗？→ 写进 `CLAUDE.local.md`。
2. 换一个用同样技术栈的项目，这条还成立吗？→ 成立就写进 **L3** 对应的技术栈文件，文件不存在就新建，例如 `vitest.md`。
3. 其它情况 → 写进 **L2** 对应的类别文件。

### 4. 去重
写入前先执行 `lessons search "P" --tags <标签> --kw <关键词>`，检查有没有相同或相近的条目：
- **同一件事**：更新原条目，把措辞改得更准，在来源后追加本次编号。不要新增。
- **相近**：合并成一条更通用的表述，保留较小的编号。
- **与旧条目矛盾**：以本次验证过的事实为准，替换旧条目。

### 5. 晋升与控制规模
执行 `lessons stats "P"`，按输出处理：
- **L2 → L3**：命中 ≥2 次，并且属于技术栈通用的经验 → 移到 L3，编号改为新的 `G` 号，在原位置删除。
- **L2 → L1 铁律**：命中 ≥3 次，并且属于本项目每次都必须遵守的规则 → 精简成一行写进 AGENTS.md「铁律」，L2 原条目移到 `archive.md`。
- **超限文件**（超过 50 条）：合并同类条目，把最旧且命中最少的条目移到同目录的 `archive.md`。
- **AGENTS.md 超过 30 行**：把最不常用的铁律降回 L2。

### 6. 汇报
返回给 Queen：命中 +1 几条，新增几条（分别写到了哪一层），更新、晋升、归档各几条。
